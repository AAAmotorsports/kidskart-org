# 本番導入前の通しテスト手順

v1 を A-ONE で使い始める前に、**自分たちで一度ぜんぶ触る**ための手順書。
上から順に 1 回やれば、実際の運用で通る道はほぼ全部通る。

* 所要: 60〜90 分
* 使うもの: PC 1 台 + スマホ 1 台 + 受信できるメールアドレス 2 つ
  (1 つは「お客様役」、1 つは `MAIL_ADMIN_TO` = 管理者通知の受信用)
* 本番の Supabase をそのまま使う。最後に **§13 後片付け**でテスト予約を消す。

URL は `https://reserve.rk-a1.com` を `<BASE>` と書く
(`https://aone-booking.kidskart1177.workers.dev` も同じものを指す)。

---

## 0. 事前設定 (これが済んでいないと §6 以降が動かない)

| どこ | 名前 | 状態 |
|---|---|---|
| Cloudflare → 変数とシークレット → **シークレット** | `SUPABASE_SERVICE_ROLE_KEY` | 済 |
| 同上 | `RESEND_API_KEY` | ☐ **未登録なら登録する** |
| 同上 | `CRON_SECRET` | ☐ |
| GitHub → Settings → Secrets → Actions | `AONE_API_BASE` = `<BASE>` | ☐ |
| 同上 | `AONE_CRON_SECRET` = Cloudflare の `CRON_SECRET` と同じ値 | ☐ |

`RESEND_API_KEY` が無い間、メールは**エラーにならず黙ってスキップ**される
(画面のテストは全部できる / メールだけ届かない)。

差出人は現在 `noreply@kidskart.org`、返信先・管理者宛は `info@kidskart.org`。
A-ONE のアドレスに変えたい場合は Resend で `rk-a1.com` のドメイン認証をしてから
`wrangler.jsonc` の `MAIL_*` を差し替える (`vars` ブロックは消さない)。

## 1. 表示 (お客様目線)

- [ ] `<BASE>/` … 今日の状況。**カート / ミニバイク**が出ている
- [ ] キッズカート・その他は「予約が入っている日だけ」出る
- [ ] RP の空き時間チップが出ていて、押すと `/reserve/rp?date=&time=` に飛ぶ
- [ ] `<BASE>/schedule` … 月曜始まり / 各日 AM・PM の 2 行
- [ ] 右端 (土・日) が切れていない
- [ ] `?mode=rental` … RP・貸切だけ + イベント
- [ ] `?mode=sport` … スポーツ走行だけ + イベント
- [ ] `?mode=both` … 両方
- [ ] 12:00 開始・12:30 開始のレンタルが **PM 行**に出る
- [ ] **スマホ**で `/schedule` … 1 日 1 行の縦長 / 左に日付・右に AM PM
- [ ] 電話番号の表示が **092-919-7186**

## 2. スポーツ走行を Web から予約する

- [ ] `<BASE>/reserve` … RP が一番目立つ位置にある
- [ ] `/reserve/sport` で 明日 / AM / カート / 1 名 で申し込む
- [ ] 完了画面に**予約番号**と**専用 URL** が出る → URL をメモ
- [ ] お客様役のメールに「ご予約完了」が届く (専用 URL 入り)
- [ ] `/admin/day/<明日>` に今の予約が出ている
- [ ] `/admin/calendar` の該当日にカテゴリー色 + お客様名が出ている
- [ ] `/schedule` の該当日 AM に「カート」が出る (**名前は出ない** = 仕様どおり)

## 3. 予約を変更する (お客様が自分で)

- [ ] 専用 URL `<BASE>/r/<token>` を開く → 予約内容が出る
- [ ] 人数を 1 → 2 に変更 → 反映される
- [ ] **【ご予約内容の変更】のメールが届く**（変更後の内容・金額が載っている）
- [ ] RP で 3 名 → 5 名にすると **金額が 19,800 → 33,000 円に変わる**
- [ ] 日付を「クラスが埋まっている日」に変更してみる → **断られる**
  (受付ルールが変更時にも再判定されることの確認)
- [ ] 管理画面側にも変更が反映されている
- [ ] **`info@rk-a1.com` に「✏️変更」の通知が届く**（変更点の差分が載っている）

## 4. キャンセルする

- [ ] 専用 URL からキャンセル → **連絡があれば当日でも無料**と表示される (種別を問わず)
- [ ] `/admin/reservations` で status が `cancelled` になっている
- [ ] `/schedule` からその予約が消える
- [ ] **`info@rk-a1.com` に「❌キャンセル」の通知が届く**
- [ ] 管理画面から**無断キャンセル**として処理すると、キャンセル料 100% の扱いになり
      顧客ページ (`/admin/customers/<id>`) の無断キャンセル数が増える

## 5. RP (レースパック)

- [ ] `/reserve/rp` で 3 名未満 → **断られる**
- [ ] 3 名 / 10:00〜17:00 の 30 分刻みで予約できる
- [ ] 同じ開始時刻に 3 組目 → **断られる** (1 開始時刻 2 組まで)
- [ ] 17:30 開始 → **要相談 (checking)** になる。管理者に通知メール
- [ ] 同時間帯に RP が 3 組になると、その帯のスポーツ走行が受付停止になる
- [ ] `/schedule?mode=rental` に **時刻 + 名前** で出る (12:00 以降は PM 行)
- [ ] 料金が **6,600 円 × 人数**で入っている (`/admin/reservations`)

## 6. 貸切

- [ ] 他の予約がある時間帯に申し込む → **連絡待ち (pending)** で受け付けられる
- [ ] 管理画面で **確定**にすると、その時間帯が全部止まる
  (`/` と `/schedule` で ✕ になる)
- [ ] 料金が **11,000 + 11,000 × 台数 (最小 5 台 = 66,000 円)** で入っている
- [ ] 貸切の名前は `/schedule` で**略さずフル表示**される

## 7. ナイター

- [ ] `/reserve/night` … **RP か貸切しか選べない** (通常走行の選択肢が無い)
- [ ] 申し込むと **要相談**扱い。管理者に通知が飛ぶ

## 8. 電話予約 (いちばん使う機能)

- [ ] `/admin/day/<日付>` の 📞 の赤いカードから代理入力
- [ ] **複数日 × AM/PM をまとめて**入れられる (日付チップを複数選択)
- [ ] レンタル (RP・貸切) を選んだときは AM/PM の ○✕ が出ない
- [ ] メールアドレス無しでも登録できる
- [ ] 登録直後に `/` `/schedule` の空き表示が変わる
- [ ] 同じ電話番号でもう 1 件入れると、**同じ顧客にひも付く** (名寄せ)
- [ ] 予約カードの **「✏️ 日時・人数を変更」** から日付・時間帯・人数を変えられる
- [ ] 「変更内容をお客様にメールで知らせる」のチェックを外すと、メールが飛ばない

## 9. 天候変更

- [ ] `/admin` の天候ワンタップ (☀ 通常 / 🌧 雨天中止 / ⚠ 一部変更) を押す
- [ ] `/` の表示が即座に変わる
- [ ] 同じ画面の一括連絡フォームで、その日の予約者全員にメール送信
- [ ] お客様役のメールに届く
- [ ] `/admin/day/<日付>` に送信履歴が残る

## 10. 受付シート

- [ ] `<BASE>/admin/sheet` … 今日の Web / 電話 / 店頭の予約が**時刻順**に並ぶ
- [ ] スポーツ走行は AM=09:00 / PM=13:00 の位置に入る
- [ ] スマホで見られる
- [ ] **A4 で印刷**して崩れない (ブラウザの印刷プレビュー)

## 11. 自動メール (cron)

> ⚠️ curl で叩くときは **`Content-Type: application/json` を必ず付けて**ください。
> 付けないと Astro の CSRF 対策で 403 (`Cross-site POST form submissions are
> forbidden`) になります。cron 本体の問題ではありません。

前日リマインド / 当日お礼 / 2 週間後フォロー。手動で叩いて確認する:

```bash
curl -X POST "<BASE>/api/cron/mails?type=reminder&date=$(date -d tomorrow +%F)" \
  -H "x-cron-secret: <CRON_SECRET>" \
  -H "Content-Type: application/json"
```

- [ ] `sent` が 1 以上で返る
- [ ] お客様役にリマインドが届く
- [ ] **もう一度同じコマンド** → `skipped` になる (二重送信しない)
- [ ] `type=thanks` / `type=followup` も同様に確認
- [ ] GitHub Actions の `aone-mails` を手動実行 → 成功する

## 11-2. 折り返し対応と督促

- [ ] 貸切を「他の予約がある日」に申し込む → **連絡待ち**になる
- [ ] 管理者宛メールの件名が **🔴要折り返し** で始まる
- [ ] お客様宛メールの件名が **【まだ確定していません】** で、
      48 時間以内に折り返す旨と電話番号が書かれている
- [ ] `/admin` と `/admin/day/<日付>` に「折り返し未対応」の赤い警告が出る
- [ ] **「📞 電話で対応済」** を押す → 「対応済」バッジに変わり、警告から消える
- [ ] 「対応済を取消」で元に戻る
- [ ] 督促メールを手動で確認 (`hours=0` なら受付直後のものも対象になる):

```bash
curl -X POST "<BASE>/api/cron/mails?type=callbacks&hours=0" \
  -H "x-cron-secret: <CRON_SECRET>" \
  -H "Content-Type: application/json"
```

- [ ] `info@rk-a1.com` に「🔴要折り返し N 件」が届く
- [ ] 対応済みにしてからもう一度叩くと、その予約が一覧から消える

## 13. 後片付け

テストで作った予約・顧客を消す。Supabase → SQL Editor:

```sql
-- テストで使ったメールアドレス / 電話番号で絞ってから消すこと
delete from aone_reservations where contact_email = 'テストで使ったアドレス';
delete from aone_customers    where email          = 'テストで使ったアドレス';
```

- [ ] `/schedule` `/admin/calendar` からテスト予約が消えた
- [ ] 天候設定を **通常**に戻した
- [ ] テストで作ったブロック (レース / 臨時休業) を消した
